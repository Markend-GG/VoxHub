# 截图白名单目标模式 Spec

状态：ready for target mode  
优先级：P1  
日期：2026-06-27  
目标分支：`codex/context-capture`  
上游依据：

- `docs/context-capture-target-mode.md`
- `docs/context-vision-analysis-target-mode.md`
- `docs/report-generation-and-enter-capture-target-mode.md`
- 用户确认的产品决策：只按应用/进程做截图白名单；未命中完全不记录；白名单默认开启；白名单控制语音、重写、截图记录三类截图。

## 0. 目标模式执行契约

这份文档用于后续目标模式开发，执行时不需要再额外拆解。目标模式必须遵守：

- 以本文件为实现依据，优先形成可测试闭环，再补充边缘场景。
- 不改动 ASR、本地模型、语音润色主流程、文本重写插入策略、剪贴板回退策略。
- 不破坏已有语音历史、重写历史、上下文采集、截图分析、截图记录、历史报告。
- 白名单是截图前置过滤层，不是历史筛选层。
- 未命中白名单时必须完全静默跳过，不创建任何历史或上下文记录。
- 白名单配置必须持久化，重启 OpenLess 或重启电脑后仍然有效。
- 当前版本只做 Windows 应用/进程白名单；不做窗口标题规则、不做排除词、不做主题识别。
- V1 只在 Windows 启用截图白名单 UI；非 Windows 不展示该管理入口。

## 1. 背景与问题

OpenLess 已支持在语音输入、文本重写、截图记录时采集截图，并可将截图交给多模态 LLM 分析。全局截图能力提升了上下文质量，但也带来隐私风险：用户可能在私人聊天、密码页面、支付页面、非工作应用中触发截图记录。

本需求通过“截图白名单”把截图范围限定在用户允许的应用进程中：

- 保护隐私：非白名单应用完全不截图、不分析、不落历史。
- 降低性能消耗：未命中时跳过截图、压缩和 LLM 分析。
- 提升统计价值：只采集工作相关应用的数据，方便后续日报、周报、月报生成。

## 2. 目标

新增“截图白名单”能力：

- 默认开启白名单过滤。
- 默认内置一组工作应用白名单。
- 用户可在设置中通过弹窗管理白名单。
- 用户可从当前正在打开的应用列表中选择应用加入白名单。
- 三类截图都受白名单控制：
  - 语音历史上下文截图
  - 重写历史上下文截图
  - 截图记录
- 未命中白名单时完全不记录。
- 托盘菜单中的截图记录控制改为选项式交互，提供“开启记录”和“暂停记录”两个勾选项。

## 6. 数据模型

### Preferences 新增字段

```ts
type ScreenshotWhitelistAppSource = "default" | "user";

interface ScreenshotWhitelistApp {
  id: string;
  displayName: string;
  processName: string;
  exePath?: string | null;
  source: ScreenshotWhitelistAppSource;
  createdAt: string;
}

interface Preferences {
  screenshotWhitelistEnabled: boolean;
  screenshotWhitelistApps: ScreenshotWhitelistApp[];
  screenshotWhitelistDefaultsVersion: number;
}
```

Rust 类型需与 TypeScript 保持 camelCase 序列化一致。

### 现有历史保留字段调整

现有历史条数保留字段继续沿用：

```ts
interface Preferences {
  historyMaxEntries: number | null;
}
```

本期需要同步调整前后端默认值和输入约束：

- 默认值：`2000`
- 最小值：沿用当前最小值，建议保持 `5`
- 最大值：`10000`
- 空值语义：如果 UI 仍允许清空输入，则清空后应回落到默认值 `2000`，不得再回落到旧默认 `200`
- 后端持久化和清理逻辑必须使用同一套默认值与最大值，不能只改前端输入框

### 默认值

- `screenshotWhitelistEnabled`: `true`
- `screenshotWhitelistApps`: 默认白名单列表
- `screenshotWhitelistDefaultsVersion`: `1`
- `historyMaxEntries`: 缺省或为空时按 `2000` 处理

### 迁移策略

- 旧 `preferences.json` 缺少白名单字段时：
  - 自动填充默认白名单。
  - 自动设置 `screenshotWhitelistEnabled = true`。
- 旧 `preferences.json` 缺少 `historyMaxEntries` 或值为 `null` 时：
  - 按新的默认值 `2000` 处理。
- 旧 `preferences.json` 已明确设置 `historyMaxEntries` 时：
  - 保留用户已有值。
  - 如果已有值超过新上限 `10000`，保存或下次编辑时应 clamp 到 `10000`。
- 如果用户已经存在白名单配置：
  - 不覆盖用户删除或新增的条目。
  - 后续升级新增默认项时，只在 `screenshotWhitelistDefaultsVersion` 小于当前版本时做补充，且不得恢复用户已删除的默认项，除非实现了显式的 deleted-default 记录。
- V1 为避免误恢复用户删除项，建议默认版本固定为 `1`，新增默认项优先依赖“恢复默认白名单”手动执行。

## 7. Windows 进程识别

### 前台应用识别

新增 Windows-only 能力：

```rust
pub(crate) struct ForegroundAppIdentity {
    pub process_name: String,
    pub process_id: u32,
    pub exe_path: Option<String>,
    pub display_name: Option<String>,
    pub window_title: Option<String>,
}

pub(crate) fn current_foreground_app_identity() -> Option<ForegroundAppIdentity>;
```

实现要求：

1. 调用 `GetForegroundWindow` 获取前台窗口句柄。
2. 调用 `GetWindowThreadProcessId` 获取 PID。
3. 通过 PID 获取进程名。
4. 尝试获取 exe 路径和文件描述，失败不阻断。
5. 过滤 OpenLess 自己的进程，避免用户把设置页误加入。
6. 任一步关键失败则返回 `None`。

白名单判断中，`None` 必须按未命中处理。

关键失败只包含无法获取前台窗口、PID 或进程名。exe 路径、图标、文件描述读取失败时，只影响 UI 展示，不影响按进程名匹配。

### 可见窗口应用枚举

新增 IPC 用于弹窗选择：

```rust
#[tauri::command]
fn list_open_window_apps() -> Result<Vec<OpenWindowApp>, String>;
```

```ts
interface OpenWindowApp {
  processName: string;
  processId: number;
  displayName: string;
  exePath?: string | null;
  windowTitle?: string | null;
}
```

实现要求：

- 枚举当前可见顶层窗口。
- 过滤不可见窗口、空标题窗口、系统窗口、OpenLess 自己窗口。
- 同一 `processName + exePath` 去重。
- 如果同一应用有多个窗口，可取最近枚举到的窗口标题作为辅助展示。
- 不需要后台轮询，只在打开弹窗或点击刷新时枚举。

## 8. 白名单判断规则

新增函数：

```rust
pub(crate) fn screenshot_allowed_by_whitelist(prefs: &Preferences) -> bool;
```

逻辑：

1. 如果白名单开关关闭，返回 `true`。
2. 如果白名单开关开启，读取当前前台进程。
3. 如果读取失败，返回 `false`。
4. 将当前 `process_name` 转为小写。
5. 与 `screenshotWhitelistApps[].processName` 小写值匹配。
6. 命中返回 `true`，未命中返回 `false`。

不得用窗口标题参与 V1 判断。

## 9. 截图触发点接入

白名单判断必须在截图、压缩、LLM 分析、历史记录创建之前执行。

### 语音上下文截图

接入点：`Coordinator::spawn_context_capture` 或其调用前。

规则：

- `context_capture_enabled = false`：直接返回。
- `screenshotWhitelistEnabled = true` 且未命中：直接返回。
- 命中后才启动上下文采集线程。

未命中时：

- 不创建 `ContextCaptureEntry`
- 不创建截图文件
- 不触发截图分析
- 不影响语音主流程
- 不在语音历史详情展示跳过状态

### 重写上下文截图

同语音上下文截图。

额外保持现有规则：

- 如果 `rewrite_save_history = false`，仍然不采集重写上下文。

### 截图记录

接入点：`handle_screenshot_record_hotkey`。

顺序建议：

1. 读取截图记录偏好。
2. 如果 `screenshot_record_enabled = false` 或 `screenshot_record_paused = true`，返回。
3. 白名单判断。
4. 未命中直接返回。
5. 执行语音/重写重复 Enter 去重。
6. 执行 1 分钟合并、截图、分析。

未命中时：

- 不创建 `ScreenshotRecord`
- 不创建截图文件
- 不触发压缩
- 不调用 LLM
- 不创建任何跳过历史

截图记录合并窗口必须遵守白名单边界：

- 每次快捷键触发都必须先做白名单判断。
- 未命中时不得创建、追加或延长任何截图记录合并窗口。
- 合并窗口内如果切换到另一个白名单应用，建议新建截图记录，不合并到上一应用记录。
- 合并判断至少应包含 `processName`，避免同一条截图记录混入多个应用场景。

标题：`截图白名单`

- 关闭白名单时必须提示：
  - `关闭后，OpenLess 将不再限制应用，所有应用都可能被截图记录。`

  - `浏览器加入白名单后，OpenLess 可能记录当前浏览器页面内容，请谨慎使用。`
- 白名单列表：
  - 应用名称
  - 进程名
  - 来源：默认 / 用户添加
  - 删除按钮
- 操作按钮：
  - `添加应用`
  - `恢复默认白名单`
  - `关闭`

### 添加应用弹窗

点击 `添加应用` 后展示当前正在打开的应用列表。

列表字段：

- 应用名称
- 进程名
- 窗口标题辅助信息
- 已在白名单中状态
- 添加按钮

交互：

- 打开弹窗时调用 `list_open_window_apps`。
- 支持 `刷新`。
- 已加入白名单的应用显示为已添加，不重复添加。
- 添加后立即持久化到偏好。
- 添加失败时显示错误提示，不影响其它设置。

### 删除应用

- 默认项和用户项都允许删除。
- 删除后立即持久化。
- 如果用户误删，可通过 `恢复默认白名单` 重新加入默认列表。

### 恢复默认白名单

行为：

- 将默认白名单中缺失的条目重新加入。
- 不删除用户自定义条目。
- 不重复添加已有进程名。

## 11. 托盘菜单截图记录改造

当前托盘菜单中的截图记录控制需要改为选项式交互，类似选择麦克风的交互方式。

### 菜单结构

父级：`截图记录`

子项：

- `开启记录`
- `暂停记录`

### 状态映射

| 偏好状态 | 菜单显示 |
| --- | --- |
| `screenshot_record_enabled = true` 且 `screenshot_record_paused = false` | 勾选“开启记录” |
| `screenshot_record_enabled = true` 且 `screenshot_record_paused = true` | 勾选“暂停记录” |
| `screenshot_record_enabled = false` | 两项都不勾选，或禁用该父级下的暂停项，按现有托盘模式选择一致实现 |

### 点击行为

- 点击 `开启记录`：
  - 设置 `screenshot_record_enabled = true`
  - 设置 `screenshot_record_paused = false`
  - 更新截图记录热键监听
  - 刷新托盘菜单勾选状态
- 点击 `暂停记录`：
  - 设置 `screenshot_record_enabled = true`
  - 设置 `screenshot_record_paused = true`
  - 取消或忽略后续截图记录触发
  - 刷新托盘菜单勾选状态

### 约束

- 该改造只影响截图记录功能，不影响语音、重写、麦克风选择、模型选择。
- 菜单状态必须和设置页中的截图记录开关、暂停状态保持一致。
- 暂停记录时，不创建截图记录，不触发截图分析。

## 12. 历史条数上限优化

当前设置页历史条数输入最大值为 200，无法覆盖截图记录、语音历史、重写历史和后续报告生成需要的长期回溯场景。本期将历史保留条数默认值提升到 2000，并允许用户配置到 10000。

### 产品规则

- 默认保留条数：`2000`
- 用户可配置范围：`5` 到 `10000`
- 设置为空：按默认 `2000` 处理
- 设置超过 `10000`：前端输入限制，后端保存时也必须 clamp
- 设置低于 `5`：前端输入限制，后端保存时也必须 clamp
- 已有用户明确设置的历史条数不强行覆盖，除非值为空或字段缺失

### 作用范围

该字段继续作为现有全局历史条数上限使用，至少覆盖：

- 语音历史
- 重写历史
- 上下文采集记录
- 截图记录

如果历史报告使用独立保存策略，目标模式执行时需要检查是否也复用 `historyMaxEntries`。若报告历史已有独立上限，应在实现总结中说明，不得静默混用。

### UI 要求

设置页“历史条数上限”输入框：

- `max` 从 `200` 改为 `10000`
- placeholder 从 `200` 改为 `2000`
- 说明文案如存在，应同步改为：
  - `留空使用默认值 2000，最大 10000。`

### 后端要求

- Rust 默认偏好值从旧默认 `200` 调整为 `2000`。
- 后端保存偏好时做范围校验，避免绕过前端写入过大值。
- 历史清理逻辑继续使用 `historyMaxEntries`，但默认 fallback 必须变为 `2000`。
- 不改变历史保留天数 `historyRetentionDays` 的语义。

### 性能说明

`2000` 作为默认值在当前 JSON 存储模式下相对稳妥，能满足语音、重写、截图记录和报告生成的常规回溯需求。`10000` 作为最大值给重度用户保留空间，但目标模式开发时应避免在前端无分页地渲染超大列表；如当前历史页仍是一次性列表，后续应评估分页或虚拟列表。

## 13. 隐私与安全

- 未命中白名单时不保存窗口标题、不保存进程名、不保存跳过记录。
- 白名单判断失败时按未命中处理。
- 不在日志中输出完整窗口标题、完整 exe 路径，除非 debug 日志已明确允许。
- 不把白名单数据发送给 LLM。
- 不把 API Key、Token、Cookie、完整 URL 写入白名单日志。
- 浏览器默认加入白名单，但 UI 必须提示潜在风险。
- 浏览器隐私模式、无痕窗口、私人网页在 V1 无法识别；浏览器一旦命中白名单，同一浏览器进程下的页面都可能被截图。

## 14. 边界条件

### 非 Windows 平台

V1 只在 Windows 启用截图白名单 UI。

- macOS / Linux 不展示“截图白名单”设置入口。
- macOS / Linux 不提供“添加应用”弹窗和进程枚举能力。
- macOS / Linux 保持现有截图行为，不因为本需求引入不可用 UI。
- 如果后端公共逻辑被调用且无法获取进程，按未命中处理，避免隐私风险。

### OpenLess 自身窗口

OpenLess 自己的窗口不得进入截图白名单候选，也不应被截图记录。

- 设置页、历史页、白名单弹窗、报告页等 OpenLess 窗口必须从“添加应用”列表中过滤。
- 如果截图触发时前台窗口是 OpenLess 自己，白名单开启时应按未命中处理。
- 不允许通过“恢复默认白名单”把 OpenLess 自己加入默认列表。

### 系统敏感窗口

安全桌面、锁屏、UAC、系统凭据输入等窗口不应被截图。

- 如果无法正常获取前台窗口或进程，按未命中处理。
- 不尝试绕过系统权限截图。
- 不创建跳过历史。

### 进程识别失败

场景：

- 前台窗口句柄为空。
- PID 读取失败。
- 进程已退出。
- 权限不足。

处理：

- 返回未命中。
- 不截图。
- 不写历史。

### 进程附加信息读取失败

场景：

- exe 路径读取失败。
- 文件描述读取失败。
- 图标读取失败。

处理：

- 如果进程名已成功读取，白名单判断继续进行。
- UI 展示字段缺失时回退到 `processName`。
- 不因为附加信息失败而拒绝已命中的进程名。

### 白名单为空

如果 `screenshotWhitelistEnabled = true` 且白名单为空：

- 所有应用都不截图。
- 设置弹窗显示空状态：
  - `当前没有白名单应用。开启后，OpenLess 不会记录任何截图。`

### 白名单关闭

如果 `screenshotWhitelistEnabled = false`：

- 不执行进程匹配。
- 只要对应截图总开关开启，就允许截图。
- UI 必须清楚提示关闭后所有应用都可能被截图。

### 默认项被删除

- 删除后立即生效。
- 后续启动不自动恢复。
- 用户点击 `恢复默认白名单` 才恢复。
- 恢复默认白名单时按 `processName` 去重，已有项不覆盖。

### 应用多进程

Chrome、Edge、Office 等可能存在多进程。

- 白名单只匹配前台窗口所属进程。
- 不枚举子进程。
- 不按后台服务进程判断。

### 同一进程多窗口

同一进程下的不同窗口不做区分。

- Chrome 工作页和私人页都属于 `chrome.exe`，V1 无法按网页或窗口标题区分。
- 企业微信不同会话窗口如属于同一进程，V1 也不区分。
- 这是应用层白名单的已知限制，通过浏览器风险提示和后续窗口层规则缓解。

### 进程名冲突

V1 只按 `processName` 匹配，存在同名可执行文件误命中的风险。

- 例如非官方程序也可能命名为 `chrome.exe`。
- V1 接受该限制。
- 后续可升级为 `processName + publisher` 或 `processName + exePath` 的高级匹配。

### 应用升级或进程名变化

默认白名单不保证覆盖所有版本和安装渠道。

- 如果应用升级后进程名变化，白名单可能不再命中。
- 用户可通过“添加应用”补齐实际识别到的进程。

### 终端应用

Codex、Claude Code 等如果运行在终端中：

- V1 只能识别终端进程。
- 用户可以把终端加入白名单。
- 不在 V1 中区分终端内部具体命令。

### 老用户升级后的空白历史感知

老用户升级后白名单自动开启，非白名单应用不会产生截图记录。

- 设置说明必须提示：未命中白名单不会留下任何记录。
- 如果用户认为截图失效，应能在设置中看到“仅记录白名单应用”开关和当前白名单。

### 截图文件和历史清理

历史条数上限提升后，截图文件仍必须跟随对应历史或上下文记录清理。

- 删除单条历史时，应删除关联截图文件。
- 历史保留周期或条数清理时，应清理对应截图文件。
- 清理截图失败只记录日志，不阻断历史清理。
- 不允许因为截图文件清理失败而重新创建历史记录。

## 15. 竞态处理

### 偏好读取竞态

截图触发时读取一次当前偏好快照即可。

- 如果用户刚好切换白名单开关，以触发时读取到的偏好为准。
- 不需要等待设置写入完成。

### 偏好并发写入

设置页、托盘菜单、白名单弹窗、历史条数输入都可能修改同一份偏好。

- 后端命令必须基于最新 `PreferencesStore` 做局部更新，不得要求前端提交整份旧 prefs 后覆盖保存。
- 偏好写入必须序列化，避免并发写文件互相覆盖。
- 每个保存命令返回最新偏好快照。
- 前端收到保存结果后刷新本地状态。

### 历史条数保存竞态

历史条数上限和其它设置可能同时保存。

- `historyMaxEntries` 保存时必须在后端 clamp 到 `5..=10000`。
- 其它偏好保存不得覆盖刚刚更新的 `historyMaxEntries`。
- `historyMaxEntries = null` 的解释必须统一为默认 `2000`。

### 前台窗口变化

截图触发时读取当前前台进程。

- 如果读取后用户切换窗口，仍以触发瞬间读取结果为准。
- 不做二次确认。

### 异步上下文采集窗口漂移

语音和重写的上下文采集是旁路异步任务。用户触发后可能立即切换窗口。

- 白名单判断必须发生在触发瞬间。
- 触发瞬间未命中时，不启动采集任务。
- 触发瞬间命中后，可以启动采集任务；采集任务不应重新用“当前窗口是否命中白名单”推翻触发时决策。
- 截图内容仍按现有上下文采集逻辑截取执行时的活动窗口；如果后续要严格绑定触发窗口，需要另开窗口句柄级截图方案。

### 截图记录合并竞态

截图记录支持 1 分钟合并窗口。

- 每次 Enter 触发都必须先做白名单判断。
- 未命中白名单时，不得追加到已有合并记录。
- 未命中白名单时，不得延长已有合并窗口。
- 如果当前命中的 `processName` 与活动合并记录的 `processName` 不同，应新建记录或结束旧记录后新建，不能混合写入同一条记录。

### 添加应用列表过期

用户打开“添加应用”弹窗后，应用可能关闭。

- 添加时仍按列表中的 `processName` 写入白名单。
- 不要求进程仍然存活。
- 添加时再次按小写 `processName` 去重。
- 多个窗口对应同一 `processName` 时，只允许写入一条白名单项。

### 删除与截图同时发生

如果用户删除白名单项的同时触发截图：

- 以截图触发时读取到的偏好快照为准。
- 下一次触发必须使用最新偏好。

### 删除与恢复默认同时发生

用户可能连续点击删除默认项和恢复默认白名单。

- 后端必须按小写 `processName` 做唯一键。
- 恢复默认时不重复添加已有项。
- 已有用户自定义项与默认项 `processName` 相同时，不覆盖用户自定义显示名。

### 托盘状态与设置页状态

设置页和托盘都能修改截图记录状态。

- 修改后必须更新同一份偏好。
- 修改后必须刷新托盘菜单。
- 托盘点击后必须广播偏好变化事件，或触发前端重新读取偏好。
- 前端状态通过现有偏好刷新或事件同步，不能长期显示旧状态。

### 历史清理与分析回填

截图分析、语音上下文分析、重写上下文分析可能晚于历史清理完成。

- 分析完成时，如果目标历史或上下文记录已被删除，回填应 no-op。
- 不得为了写入分析结果重新创建已删除的历史记录。
- 如果截图文件已被清理，分析任务应失败或跳过，并记录状态，不得崩溃。

## 16. IPC 与命令

建议新增或扩展以下 IPC：

```ts
listOpenWindowApps(): Promise<OpenWindowApp[]>
setScreenshotWhitelistEnabled(enabled: boolean): Promise<Preferences>
addScreenshotWhitelistApp(app: ScreenshotWhitelistAppInput): Promise<Preferences>
removeScreenshotWhitelistApp(processName: string): Promise<Preferences>
restoreDefaultScreenshotWhitelistApps(): Promise<Preferences>
```

输入类型：

```ts
interface ScreenshotWhitelistAppInput {
  displayName: string;
  processName: string;
  exePath?: string | null;
}
```

命令实现要求：

- 所有 `processName` 入库前统一小写。
- 同一 `processName` 不重复添加。
- `displayName` 为空时回退为 `processName`。
- 修改后立即持久化偏好。

## 17. 测试计划

### Rust 单元测试

- 默认偏好包含白名单开关和默认白名单。
- 旧偏好反序列化时自动补默认字段。
- 历史条数默认值为 2000。
- 历史条数保存时最大 clamp 到 10000。
- `historyMaxEntries = null` 时按 2000 处理。
- 进程名匹配大小写不敏感。
- 白名单关闭时允许截图。
- 白名单开启且未命中时拒绝截图。
- 进程识别失败时拒绝截图。
- 添加重复进程名不会重复写入。
- 恢复默认白名单不删除用户自定义项。

### 前端测试

- 设置页能打开“截图白名单”弹窗。
- 开关文案和状态正确。
- 白名单列表展示默认项。
- 删除应用后列表更新。
- 恢复默认白名单后默认项恢复。
- 添加应用弹窗能展示正在打开的应用列表。
- 已添加应用不重复添加。
- 浏览器风险提示可见。
- 历史条数上限输入框最大值为 10000，placeholder 或默认提示为 2000。

### 托盘测试

- 截图记录菜单展示为选项式交互。
- 正常记录时勾选“开启记录”。
- 暂停时勾选“暂停记录”。
- 点击“开启记录”后恢复截图记录热键。
- 点击“暂停记录”后不再创建截图记录。
- 托盘和设置页状态一致。

### 手工验证

1. 白名单开启，当前应用在白名单：
   - 触发语音输入，历史详情有截图。
   - 触发文本重写，重写历史详情有截图。
   - 按 Enter 截图记录，截图记录历史有记录。
2. 白名单开启，当前应用不在白名单：
   - 触发语音输入，不产生上下文截图。
   - 触发文本重写，不产生上下文截图。
   - 按 Enter，不产生截图记录。
   - 不出现跳过历史。
3. 白名单关闭：
   - 任意应用都可按原总开关规则截图。
4. 获取进程失败模拟：
   - 不截图，不写历史。
5. 重启 OpenLess：
   - 白名单开关和列表仍保留。
6. 重启电脑后打开 OpenLess：
   - 白名单配置仍保留。

## 18. 验收标准

- 默认开启截图白名单。
- 默认白名单包含本文件列出的应用进程。
- 老用户升级后自动启用白名单且填充默认列表。
- 历史条数默认值为 2000，用户最大可配置到 10000。
- 未命中白名单时三类截图都不发生。
- 未命中白名单时不创建任何历史或上下文记录。

- 设置页可以通过弹窗管理白名单。
- 用户可以从正在打开的应用列表中添加应用。
- 白名单持久化，重启后不丢失。
- 托盘截图记录菜单改为“开启记录 / 暂停记录”选项式交互，并能正确反映状态。

## 20. 风险

- 部分应用实际进程名可能与默认列表不同，需要用户通过“添加应用”补齐。
- 浏览器按进程白名单粒度较粗，可能记录私人网页；已通过 UI 风险提示缓解。
- 终端中的 Codex / Claude Code 无法按具体工具区分；V1 接受限制。
- 过度依赖窗口标题的方案暂不采用，避免误判和复杂配置。
- 老用户升级自动开启白名单可能导致部分非白名单应用突然不截图；这是隐私优先策略，需在设置说明中明确。
- 历史条数最大值提升到 10000 后，如果前端历史页一次性渲染所有记录，低配电脑上可能出现列表卡顿；后续应评估分页、虚拟列表或按需加载。
