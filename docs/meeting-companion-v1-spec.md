## 1. Scope Authority（范围权威）

- 本文档是会议桌宠 V1 的顶层范围权威。
- 关联验收清单：`docs/meeting-companion-v1-acceptance-checklist.md`。
- 关联实施计划：`docs/meeting-companion-v1-implementation-plan.md`。
- 会议录音主链路仍以 `docs/meeting-recording-v1-spec.md` 和当前代码为准；本功能不建立第二套会议 session（会议会话）。
- 会议 ASR V2 仍以 `docs/meeting-recording-v2-plan.md` 为准；本功能不改动 provider（服务商）、转写或总结管线。
- 用户最新确认优先于本文档；如后续确认与本文档冲突，先更新 spec 和 checklist，再继续实施。

## 2. 背景

当前会议录音状态主要显示在主窗口的会议页。用户离开主页面后，容易忘记仍在录音，也需要重新打开主窗口才能暂停或停止。

会议桌宠 V1 通过一个可选、常置顶层的透明悬浮窗口，持续显示会议状态并提供暂停 / 继续 / 停止控制。视觉形象为坐在桌前记录的 2D 动漫女学生，但产品定位是“会议可见状态和快捷控制”，不是通用娱乐桌宠。

## 3. 目标

- 会议开始后，在其他应用上方持续显示录音状态和真实已录时长。
- 用户无需回到主窗口即可暂停、继续和停止当前会议。
- 用状态动画区分录音、安静、暂停、总结中和完成，降低忘记停止录音的风险。
- 悬浮窗口可拖动、吸附屏幕边缘并记住位置，不强迫用户每次重新摆放。
- 桌宠展示层失败时不能影响会议录音、ASR（语音转文字）、音频保留或总结主链路。

## 4. 已确认产品决策

- 会议桌宠是 optional mode（可选模式），默认关闭；用户开启后，会议录音开始时自动显示。
- V1 不常驻桌面，不从桌宠新建会议；开始会议仍在主会议页完成。
- 左键直接拖动角色或透明背景，不使用长按。
- 悬停或单击显示可见的暂停 / 继续与停止按钮；右键菜单只是辅助入口。
- 停止录音必须二次确认；暂停和继续不二次确认。
- 隐藏或关闭桌宠只隐藏窗口，绝不停止会议。
- 停止后显示 `processing`（整理中）；总结成功后播放一次 `completed`（已完成），停留 3 秒后自动隐藏。
- 总结失败时不播放完成动画；显示错误徽标并继续驻留 3 秒，期间用户可打开会议页，随后自动销毁桌宠窗口。
- V1 以 Windows 为强制验收平台。macOS 保留 poster / APNG（动态 PNG）回退路线，不在 V1 声称透明 WebM 已真机验证。

## 5. V1 范围

### 5.1 独立桌面窗口

- 新增独立 `meeting-companion` Tauri `WebviewWindow`（网页视图窗口）。
- 窗口按需懒创建。活跃会议期间用户手动隐藏时保留隐藏窗口以支持快速重新显示；会议完全结束且桌宠自动隐藏后销毁该窗口，无会议时不常驻额外 WebView（网页视图）。
- 窗口无边框、透明、置顶、不显示在任务栏、不允许用户自由缩放。
- 角色素材源分辨率保持 `350 x 280`；运行时等比显示为 `240 x 192` logical pixels（逻辑像素），控制区高度为 40 像素，窗口总尺寸为 `240 x 232`。
- 前端通过 `?window=meeting-companion` 路由只加载桌宠所需的最小 React 树，不加载完整 `FloatingShell` 和设置页。
- 桌宠窗口关闭请求必须转换为 hide（隐藏），不销毁活跃会议，不调用停止录音。

### 5.2 桌宠设置

- 持久化 `meetingCompanionEnabled`（是否启用），默认 `false`。
- 持久化 `meetingCompanionPositionLocked`（是否锁定位置），默认 `false`。
- 持久化最后一次合法窗口位置和显示器标识。
- 设置 UI 复用当前 `SettingsModal` 和 `SwitchLite`（开关）风格，不新增独立设置框架。
- V1 不提供角色换装、尺寸滑块、透明度或置顶开关。

### 5.3 位置与拖动

- 除按钮、菜单和确认框外，角色和透明舞台都是拖动区。
- 锁定位置后禁止拖动，但不影响悬停控制和右键菜单。
- 拖动结束后才写入持久化位置，不在 pointer move（指针移动）中频繁写盘。
- 靠近当前显示器工作区边缘 16 像素以内时吸附到边缘。
- 恢复位置时必须对当前 work area（工作区）做 clamp（边界约束），覆盖副屏负坐标、DPI 缩放变化、显示器移除和分辨率变化。
- 首次显示且无保存位置时，默认放在鼠标所在显示器的右下区域，与任务栏保留至少 16 像素间距。

### 5.4 直接控制

- 鼠标进入窗口或单击角色时显示控制区；鼠标离开后延迟 800ms 收起，避免从角色移向按钮时闪烁。
- `recording` / `quiet` 状态显示 pause（暂停）和 stop（停止）图标按钮。
- `paused` 状态显示 resume（继续）和 stop 图标按钮。
- `processing` 和 `completed` 不显示暂停或停止按钮。
- 使用项目现有图标库 / `Icon` 组件；所有图标按钮必须有 tooltip（工具提示）和可访问名称。
- 暂停、继续和停止命令执行期间禁用重复点击；返回的 meeting id（会议标识）不一致时丢弃过期结果。
- 停止按钮打开窗口内二次确认；确认后调用现有 `stopMeetingRecording(id)`，不新建停止管线。
- 停止请求失败时恢复原控件，保持原动画状态并显示可执行的错误信息。

### 5.5 右键菜单

- 桌宠区域使用自定义 context menu（上下文菜单），阻止浏览器默认菜单。
- 录音中：暂停、停止、隐藏桌宠、锁定 / 解锁位置。
- 暂停中：继续、停止、隐藏桌宠、锁定 / 解锁位置。
- 整理中 / 完成 / 失败：打开会议页、隐藏桌宠、锁定 / 解锁位置。
- 菜单中的停止操作同样必须二次确认。

## 6. 会议桌宠状态机

### 6.1 视觉状态

| Visual state（视觉状态） | 素材 | 进入条件 | 播放行为 |
| --- | --- | --- | --- |
| `hidden` | 无 | 未启用、无活跃会议、用户手动隐藏、完成后超时 | 暂停并卸载视频 |
| `idle` | `idle` | 新会议首次显示桌宠 | 播放一次后进入当前 `recording` 或 `quiet` |
| `recording` | `recording` | 会议正在录音且当前检测到语音活动 | 循环 |
| `quiet` | `quiet` | 会议正在录音且连续低于安静阈值 | 循环 |
| `paused` | `paused` | meeting status = `paused` | 循环 |
| `processing` | `processing` | 停止已接受或 meeting status = `summarizing` | 循环 |
| `completed` | `completed` | 当前会议收到 summary success（总结成功） | 播放一次，停留 3 秒后隐藏 |
| `error-overlay` | 当前视觉状态 + 错误徽标 | `transcribing_interrupted`、`summary_failed`或桌宠命令失败 | 叠加状态，不建立第七套角色素材 |

### 6.2 状态优先级

高到低的优先级为：

1. `summary_failed` -> 错误徽标，驻留 3 秒后自动销毁。
2. `summarizing` / stop accepted（停止已接受） -> `processing`。
3. `paused` -> `paused`。
4. `recording` / `transcribing_interrupted` + quiet detector（安静检测） -> `recording` 或 `quiet`。
5. summary success -> `completed`。
6. 无活跃会议 -> `hidden`。

`transcribing_interrupted`（转写中断）不代表录音中断；桌宠仍显示 `recording` / `quiet`，同时叠加警告徽标。

### 6.3 安静检测

- quiet 只是视觉状态，不切分音频，不暂停录音，不改变 ASR 请求。
- 不使用“多久没收到原文”判定 quiet，因为 batch ASR（批处理语音转文字）和 realtime ASR（实时语音转文字）行为不一致。
- 复用 recorder（录音器）已计算的 `0..1 RMS`（均方根音量），录音期间最多以 10Hz 向前端发送 `meeting:audio-level`。
- 默认进入安静：`level < 0.035` 持续 2000ms。
- 默认退出安静：`level >= 0.06` 持续 150ms。
- 使用 hysteresis（滞回阈值）避免边界音量导致 `recording` / `quiet` 频繁切换。
- 阈值在 V1 为代码常量并有单元测试，不暴露用户设置。

## 7. 素材与播放规格

### 7.1 当前素材交接

- 外部交接目录：`C:\Users\25512\Pictures\素材目录\animation-run`。
- 素材身份和动作以该目录下最终六状态为准，不从 `generated/`、`work/`或 `qa/` 导入运行时素材。
- 实施时只精确复制六个 WebM、六张 poster PNG 和精简的 runtime manifest（运行时清单）到仓库。
- 原始帧、GIF、总 atlas（图集）、生成提示词、QA 解码帧和本地构建工具不进入应用 bundle（安装包）。

### 7.2 运行时素材

| State | WebM | Poster | 期望时序 |
| --- | --- | --- | --- |
| `idle` | `idle.webm` | `idle-poster.png` | 2400ms，不循环 |
| `recording` | `recording.webm` | `recording-poster.png` | 约 900ms，无缝循环 |
| `quiet` | `quiet.webm` | `quiet-poster.png` | 约 2000ms，无缝循环 |
| `paused` | `paused.webm` | `paused-poster.png` | 2400ms，无缝循环 |
| `processing` | `processing.webm` | `processing-poster.png` | 1200ms，无缝循环 |
| `completed` | `completed.webm` | `completed-poster.png` | 约 2880ms，不循环 |

- Windows 优先使用 VP9 Alpha WebM，`350 x 280`，无音轨。
- 不能只验证 `12 frames @ 12 FPS`；必须读取实际 duration（时长）并与上表比较。当前生成脚本如忽略 `duration_ms`，实施阶段先重新编码，不用 `playbackRate`（播放速率）伪造完成动画的非等时节奏。
- 视频开始播放前显示对应 poster；视频解码失败、2 秒内未 `canplay`、播放拒绝或运行中 `error` 时回退到 poster。
- 同一时刻只允许一个桌宠视频解码和播放；状态切换时暂停旧视频、重置 `currentTime`并释放不再需要的媒体引用。
- 桌宠隐藏、窗口不可见或会议结束后必须停止视频解码。
- 系统启用 reduced motion（减少动效）时，只显示当前 poster 和状态控件，不循环播放视频。

## 8. 计时器与状态反馈

- 素材内粉色计时器屏幕保持空白，由 React 叠加真实时间文字。
- 权威基线来自 `MeetingRecordingSnapshot.elapsedMs`。录音中可以用收到 snapshot 时的 `performance.now()` 作为单调时钟基点，在前端每秒插值显示；每次新 snapshot 都重新对齐基线。
- 前端 timer（定时器）只负责显示刷新，不作为持久化时长或会议状态的权威来源。
- 录音中使用红色状态点，暂停使用琥珀色状态点，整理中使用中性动态点，错误使用红色警告徽标。
- 暂停时计时器冻结；继续后从后端 snapshot 恢复。
- 停止后保留最终录音时长，直到桌宠隐藏。

## 9. 主页面与桌宠同步

- 现有 `meeting:state`、`meeting:summary`、`meeting:error` 事件和 `getActiveMeetingRecording()` 是桌宠的业务状态来源。
- 桌宠窗口加载后先调用 `getActiveMeetingRecording()` 恢复，再订阅事件，避免错过窗口创建前的开始事件。
- 主会议页和桌宠不各自保存一套会议状态；它们可有本地展示 state（状态），但后端 snapshot 是权威状态。
- 桌宠手动隐藏后，当前会议不再自动重新弹出；主会议工作台显示“显示会议助手”命令。
- 下一场新会议仍按已启用设置自动显示。
- 多个窗口同时操作时，后端 meeting id 和当前 phase（阶段）必须阻止过期暂停、继续或停止结果覆盖新状态。

## 10. 关闭、隐藏与退出

- 点击桌宠隐藏、右键隐藏或桌宠窗口 close（关闭）均只隐藏窗口。
- 主窗口关闭和应用退出继续复用现有 `meeting:close-requested` 保护，桌宠不绕过该保护。
- 应用真正退出时可销毁桌宠窗口和视频引用。
- 会议总结成功且 `completed` 停留结束后，先停止媒体和事件监听，再销毁桌宠窗口；下一场会议重新懒创建。
- 桌宠因崩溃、WebView 异常或素材失败消失时，会议必须继续录音；主页面仍可控制。

## 11. 错误处理

- 桌宠窗口创建失败：记录日志，主会议页显示非阻断提示，会议仍继续。
- WebM 不支持或加载失败：当场降级为 poster，保留计时器和控制按钮。
- poster 也失败：显示最小状态胶囊和控制按钮，不显示空白窗口。
- 暂停 / 继续失败：回到后端最新 snapshot，显示错误提示并允许重试。
- 停止失败：不进入 `processing`，保持录音 / 暂停状态并允许重试。
- ASR 中断：录音动画继续，叠加警告徽标，用户可打开会议页查看详情。
- 总结失败：停止 `processing` 动画，显示错误徽标和“打开会议”命令，驻留 3 秒后自动销毁；销毁不得影响会议记录、原文或音频。
- 设置或位置写入失败：本次会议桌宠仍可用，只提示下次可能恢复默认位置。

## 12. 性能与资源约束

- V1 只实例化一个 `meeting-companion` 窗口。
- 桌宠可见时只播放一个源分辨率为 `350 x 280`、展示尺寸为 `240 x 192` 的透明视频；不允许六个状态在隐藏 DOM 中同时解码。
- 隐藏时暂停媒体、移除视频 `src`或卸载组件，并清理 timer（定时器）和 event listener（事件监听）。
- 应用 bundle 只包含运行时素材；不把约 6MB atlas 与 WebM 同时用于 Windows 运行时。
- 不引入 Live2D、Rive、Three.js 或新动画引擎。
- 所有桌宠展示和动画逻辑都必须与 recorder 实时回调解耦，音频回调只做现有 RMS 计算和非阻塞上报，不调用 WebView API。

## 13. 隐私、安全与无障碍

- 桌宠不新增网络请求、摄像头、屏幕捕获或会议内容持久化。
- 桌宠不显示会议原文、总结文本或参会人信息，避免在其他应用上方暴露内容。
- 所有控制按钮支持键盘焦点、`Enter` / `Space` 触发、tooltip 和屏幕阅读名称。
- 停止确认框打开时锁定焦点，`Escape` 取消，确认期间不能拖动窗口。
- 系统 reduced motion 启用时自动使用 poster 回退。

## 14. 非 V1 范围

- 桌宠常驻桌面、从桌宠新建会议、通用聊天或语音交互。
- 实时会议原文、字幕级流式文字或说话人标签。
- 系统声音采集、VAD（语音活动检测）、ASR provider 或总结管线改造。
- 自由缩放、角色换装、多角色、商店、好感度或成就系统。
- Live2D、骨骼绑定、视频生成、动态下载素材或运行时 AI 生图。
- 桌宠窗口内编辑总结、重试总结、查看完整原文或播放会议音频。
- macOS 透明 WebM 的强制真机验收。

## 15. 验收标准

1. 桌宠默认关闭；开启后，从主会议页开始会议会自动显示唯一桌宠窗口。
2. 桌宠窗口在 Windows 上无边框、透明、置顶、不进任务栏，窗口为 `240 x 232`，其中角色舞台为 `240 x 192`。
3. 首次显示播放 `idle`，然后根据当前 RMS 进入 `recording` 或 `quiet`，并在两者之间使用滞回阈值稳定切换。
4. 暂停、继续和停止操作复用现有 meeting IPC，主页面与桌宠状态一致，不产生第二场活跃会议。
5. 停止操作有二次确认；隐藏或关闭桌宠不停止录音。
6. 停止成功后显示 `processing`，总结成功后播放一次 `completed`，停留 3 秒后自动隐藏。
7. 总结失败时显示错误徽标和打开会议页入口，不播放 `completed`，驻留 3 秒后自动销毁桌宠窗口。
8. 悬停 / 单击可见控制、右键菜单、左键拖动、边缘吸附、位置记忆和位置锁定全部可用。
9. 副屏负坐标、125% / 150% DPI、拔除显示器和分辨率变化后，桌宠恢复位置不会落在屏幕外。
10. 粉色计时器显示后端权威已录时长，暂停时冻结，继续后恢复，停止后保留最终时长。
11. 六个 WebM 的尺寸、Alpha、音轨、循环方式和实际时长通过自动校验；加载失败会回退 poster。
12. 同一时刻只有一个桌宠视频解码；桌宠隐藏后无后台视频播放、无持续音量事件刷新。
13. ASR 中断、素材失败、桌宠窗口创建失败和桌宠控制命令失败均不丢失录音或会议数据。
14. 主窗口关闭和应用退出仍经过现有活跃会议保护。
15. TypeScript build（构建）、Rust 窗口 / 位置测试、状态 reducer（状态归约器）测试、音量滞回测试和 Windows Tauri 人工冒烟全部通过。

## 16. 交付门槛

- `docs/meeting-companion-v1-acceptance-checklist.md` 的所有条目必须为 `done` 或用户明确确认的 `deferred`。
- 自动验证必须针对最终 diff（差异）重新运行。
- Windows 真实桌面路径必须覆盖开始、安静切换、暂停、继续、停止、总结成功和总结失败。
- 必须人工检查透明边缘、角色跳动、控件遮挡、多屏恢复和隐藏后继续录音。
- 未完成真机验收时，不得将本功能描述为已完成。

## 17. 已知风险

- Windows 透明窗口的整个矩形区域可能拦截鼠标，V1 通过压缩窗口边界减少影响，不承诺逐像素 click-through（鼠标穿透）。
- 透明 VP9 WebM 在 Windows WebView2 中仍需实际播放验证；静态报告不能替代 Tauri 真机验证。
- 当前素材 manifest 的 `duration_ms` 与固定 `12 FPS x 12 frames` WebM 可能不一致；素材导入阶段必须以实际媒体时长阻断错误素材。
- RMS 阈值会受麦克风、输入增益和环境噪声影响；V1 先使用有滞回的保守常量，真机验收中记录误切换，不提前增加用户阈值设置。
- 独立 WebView 会增加基础内存；必须懒创建并在不可见时停止视频解码。
- 主页面和桌宠可以同时操作；任何只在前端维护的乐观状态都可能被过期结果覆盖，必须以 meeting id 和后端 snapshot 校验。
