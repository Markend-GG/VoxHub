# 13-设置页与用户体验收口

## 本次只做一个改动点

只收口本地 ASR 设置页体验。不要改底层推理。

## 信息架构建议

设置页不要暴露实现细节过多，建议分成：

```text
本地语音引擎
  provider 选择：Foundry / sherpa-onnx

模型
  当前模型
  下载状态
  切换模型
  删除模型

管线
  VAD
  标点恢复
  说话人识别
  实时预览

诊断
  runtime 状态
  模型路径
  重新检测
  打开日志
```

UI 必须根据 capabilities 禁用不支持的开关，并给出短原因。

## 成功标准

- 用户能理解当前 provider/model 是否可用。
- 不支持的开关不可点击或有明确提示。
- 模型下载/取消/删除状态准确。
- 切换 provider 后不会遗留旧模型状态。
- 中文文案自然，不暴露内部错误栈。

## 不要做

- 不改 ASR 推理。
- 不改下载器底层。
- 不做复杂 onboarding。
- 不把诊断信息堆到主界面。

## 验证

```text
无模型状态
下载中状态
下载失败状态
模型可用状态
provider 不支持某开关状态
切换 provider 状态
```

## 给 AI 的提示词

```text
请只收口本地 ASR 设置页，不改底层推理。
设置页需要根据 provider/model capabilities 显示 VAD、标点、说话人识别、实时预览开关。
不支持的能力必须禁用或显示短原因。
请复用现有 LocalAsr 页面风格，不做大改版。
完成后用 Playwright 或手动截图检查关键状态。
不要 commit。
```
