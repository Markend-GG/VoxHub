## 状态定义

- `done`：有充分自动证据或真实桌面运行证据。
- `partial`：代码已实现，但仍缺真实设备、应用或长时会议验证。
- `missing`：尚未实现或没有有效证据。
- `deferred`：只能在用户明确确认延期后使用。

## Windows 桌面人工验收

### 1. 正常双源会议

- 操作：不选择采集模式，使用耳机，本人对麦克风说话，同时播放另一段无隐私人声音频，完成开始、暂停、继续、停止和会后整理。
- 预期：界面没有采集模式控件；录音可听到两路人声；无持续削波；实时原文和会后原文包含双方内容。

### 2. 麦克风不可用

- 操作：禁用或拒绝麦克风权限，播放无隐私人声音频并开始会议。
- 预期：会议可继续；界面明确提示麦克风未录制；系统播放声音可被录制，并可进入实时和会后 ASR。

### 3. 系统声音不可用

- 操作：让所选输出设备不可用，保持麦克风可用并开始会议。
- 预期：会议可继续；界面明确提示系统声音未录制；麦克风语音仍可录制并进入实时和会后 ASR。

### 4. 两个音源均不可用

- 操作：同时禁用麦克风并让系统输出设备不可用，然后开始会议。
- 预期：会议不能进入录音中状态；错误提示同时说明两个音源不可用；不留下伪 active meeting 或空受管 WAV。

### 5. 外放已知限制

- 操作：使用外放重复双源会议。
- 预期：功能稳定；记录麦克风拾取外放的重复 / 回声程度；不宣称已做 AEC。

### 6. 三个真实会议客户端

- 操作：在腾讯会议、飞书会议、微信通话中分别直接开始一场短会议，不进行采集模式选择。
- 预期：本人和对方均可回放和识别；所选输出设备与会议客户端实际播放设备一致。

### 7. 设备故障

- 操作：会议中拔出耳机、断开蓝牙、切换默认输出设备。
- 预期：不崩溃；失效音源明确中断；另一音源仍可继续；已录音频不丢失。

### 8. 暂停、继续和停止

- 操作：双源会议暂停两次、分别继续，最后停止。
- 预期：暂停期间不采集任何音源；继续后时间轴正确；停止后系统声音不再被采集。

### 9. 长会议

- 操作：执行 1 小时双源会议，在开始、中段和结尾播放可定位的测试脉冲 / 短句。
- 预期：WAV 时长误差不超过 1 秒；两路时间轴累积偏差不超过 200 ms；无长时间缺音。

## 失败证据

失败时保留：

- 截图或录屏。
- 发生时间、会议 ID、麦克风和输出设备名称、两个音源的实际状态。
- `%LOCALAPPDATA%\OpenLess\Logs\openless.log`。
- 源码版的 `openless-all/app/tauri-dev.out.log` 和 `tauri-dev.err.log`。
- 对应受管 WAV，但不使用隐私会议音频。

## Final Gate（最终门槛）

- Windows MR-V3-SA-001～017 全部为 `done` 或有用户明确确认的 `deferred`，才能声称 Windows 系统声音采集完成。
- MR-V3-SA-018 必须在 macOS 发布前为 `done`；Windows 版不得伪装代表 macOS 已支持。
- 真实会议客户端、1 小时时钟对齐、设备故障和停止后不再采集不能只用单元测试替代。
