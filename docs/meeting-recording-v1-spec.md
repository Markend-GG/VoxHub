# 会议录音总结 V1 需求设计

## 目标

在 OpenLess 中新增独立“会议”模式，支持开始、暂停、继续、停止会议录音；录音中实时滚动展示原文；停止后基于原文自动生成会议标题、摘要、关键结论、结构化待办、风险/未决问题，并保存为本地会议记录。

## V1 范围

- 新增主导航“会议”页面。
- V1 只录麦克风，不采集系统声音。
- V1 复用当前全局 ASR provider（语音转文字服务商）和 LLM provider（大语言模型服务商）。
- 实时区域展示 ASR 原始结果，结束后统一清理标点和分段。
- 会议原文按段显示 `[说话人][时间戳] 文本`。
- V1 预留说话人字段，但默认“未区分”，不做说话人自动识别。
- 停止后自动生成固定模板会议纪要。
- 支持编辑标题、总结、待办、风险/未决问题；原文只读。
- 支持 Markdown 导出、删除会议记录、重新生成总结、音频存在时重新转写。
- 音频仍保留时，支持在会议详情流式播放原始会议音频，无需等待完整音频载入；包含播放/暂停、倍速、进度条拖动和 0%～200% 音量调节，默认音量 100%；200% 增益经过 limiter（限幅器）抑制爆音。
- 会议记录只本地保存。

## 非 V1 范围

- 不做系统声音采集。
- 不做实时说话人分离。
- 不做字幕级低延迟逐字刷新。
- 不做会议专用 ASR/LLM 配置。
- 不做 Word/PDF 导出。
- 不做云同步、提醒、第三方任务系统同步。

## 关键流程

1. 用户进入“会议”页，点击开始会议。
2. 创建 meeting session（会议会话），启动麦克风采集。
3. ASR final segment（语音识别最终片段）持续追加到实时原文。
4. 用户可暂停/继续；暂停期间不采集音频，继续后写入同一会议。
5. 用户停止会议。
6. 系统优先使用实时 ASR 文本生成最终原文。
7. LLM 自动生成标题、摘要、关键结论、结构化待办、风险/未决问题。
8. 保存会议记录。
9. 用户可查看、编辑纪要字段、导出 Markdown、删除记录。

## 原始音频保留

- V1 默认保留最近 20 场会议原始音频。
- 设置中可调整保留数量，最大 100。
- 可设置为 0，表示不长期保留音频。
- 录音期间始终保留临时音频，用于 ASR 中断后的本次会话重转写。
- 超出保留数量后，自动清理最旧会议音频，但不删除会议文本记录。
- 如果音频文件被外部删除或找不到，会议记录标记为音频缺失，不提供播放和重新转写。
- 删除会议记录时同步删除关联音频。
- 只有音频仍存在时，才允许重新转写。

## 长会议处理

- 2 小时为软限制，不强制停止。
- 超过 2 小时后，底层允许按音频/文本分段继续处理。
- 手动重新转写按固定上限分片读取 PCM（脉冲编码调制音频）并逐片调用 ASR，任何时刻都不把整场 PCM 一次性读入内存；全部分片成功后才替换旧原文。
- 分段总结不能彼此独立。
- 超过 LLM context window（上下文窗口）时，需要使用 rolling context（滚动上下文）：
  - 每段生成分段笔记。
  - 下一段处理时带入前文累计上下文。
  - 最后统一合成最终纪要，去重并合并待办。
- 用户体验仍保持“停止后自动生成”。

## 页面结构

- “会议”页默认显示：
  - 搜索框
  - 开始会议按钮
  - 会议记录列表
- 录音中切换为会议工作台：
  - 状态、时长
  - 暂停/继续
  - 停止
  - 实时滚动原文
- 会议详情：
  - 原始音频播放器（音频仍保留时显示）
  - 原文只读
  - 标题、总结、待办、风险/未决问题可编辑
  - 重新生成总结
  - 重新转写
  - 导出 Markdown
  - 删除记录

## 数据加载与渲染

- 会议列表 IPC（进程间调用）只返回标题、状态、摘要概览、原文预览、片段数量、音频状态和时间字段，不返回完整原文与完整结构化总结。
- 选中会议后才请求完整 `MeetingRecord`；快速切换时，旧详情请求结果不能覆盖新选择。
- 长原文使用 virtual scrolling（虚拟滚动），只渲染可视区域附近的片段，并支持动态行高。
- 多分段播放缓存使用临时文件完整写入、刷新并同步后再原子替换；读取前校验 WAV 头、文件长度和源 PCM 总长度，损坏缓存自动重建。
- 快速切换会议时，旧音频加载结果必须丢弃；临时 Blob URL（浏览器二进制地址）同步释放。

## 错误处理

- 麦克风启动失败：不创建正式会议记录，提示无法开始录音。
- ASR 启动前失败：不进入录音。
- 录音中 ASR 失败：保留已识别原文，状态标为“转写中断”，允许继续录音。
- 临时音频写入失败：会议可继续实时转写，但本场会议不支持重新转写。
- 总结生成失败：保留原文，标题降级为“会议记录 时间 - 总结生成失败”，允许手动重试。
- 重新生成总结：二次确认后覆盖标题、摘要、关键结论、待办、风险/未决问题。
- 关闭窗口/退出应用：提示正在录音，确认后停止录音并保存已有内容。
- 删除会议：二次确认，并删除关联音频。

## 验收标准

1. 主导航出现“会议”页，可以开始、暂停、继续、停止会议录音。
2. 录音中实时滚动显示 `[未区分][00:12:34] 文本`。
3. 停止后自动生成标题、摘要、关键结论、结构化待办、风险/未决问题。
4. 待办包含内容、负责人、截止时间、来源片段。
5. 会议记录本地保存，列表支持按标题/摘要搜索。
6. 原文只读；标题、总结、待办、风险/未决问题可编辑。
7. 支持导出 Markdown。
8. 支持删除会议记录并二次确认。
9. ASR 中断时保留已识别内容，会议可继续录音。
10. 音频存在时支持手动重新转写。
11. 总结失败时不丢原文，显示失败状态并允许重试。
12. 原始音频按最近 N 场保留，默认 20，最大 100，超出后清理最旧音频。
13. 音频仍保留时，会议详情支持流式播放原始会议音频，无需等待完整音频载入；可暂停/继续播放、拖动进度条、切换播放倍速，并在 0%～200% 范围调节音量，默认音量 100%；200% 增益启用限幅器。
14. 多分段播放缓存损坏时可自动重建，并发生成不会留下半成品；切换会议后旧音频加载结果不会覆盖当前会议。
15. 长会议重新转写按上限分片读取和分片识别，失败时保留原有原文，不随会议时长线性占用整场 PCM 内存。
16. 列表只加载会议摘要，详情按需加载；长原文只渲染可视区域附近的片段。
